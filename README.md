# Business Expense Tracker

Практическое задание к лекции № 6 «Мобильное приложение» по дисциплине «Проектирование и разработка бизнес-ориентированного программного обеспечения».

Проект расширяет показанный в лекции трекер расходов: добавляет полноценный учёт доходов, расчёт баланса, графики и синхронизацию с облачной базой Firebase.

## Задание

1. Добавить графики с использованием Kivy Garden и Matplotlib.
2. Реализовать синхронизацию с облаком через Firebase REST API.
3. Добавить категории доходов и расчёт баланса.

## Соответствие требованиям

| № | Требование | Реализация | Результат |
|---:|---|---|---|
| 1 | Графики | `build_summary_figure()` в `expense_tracker/charts.py` | Два графика: расходы и доходы по категориям |
| 2 | Синхронизация с облаком | `FirebaseClient` в `expense_tracker/cloud.py` | Загрузка, объединение и отправка операций через REST API |
| 3 | Категории доходов | `INCOME_CATEGORIES` в `expense_tracker/models.py` | Зарплата, подработка, продажи, инвестиции, подарки и прочее |
| 4 | Баланс | Свойства `total_income`, `total_expense`, `balance` | Баланс рассчитывается как доходы минус расходы |

## Этапы выполнения

### 1. Модель данных

Для каждой операции сохраняются уникальный идентификатор, тип, категория, описание, сумма, дата создания и дата изменения. Данные хранятся локально в JSON.

### 2. Доходы, расходы и баланс

Пользователь выбирает тип операции, после чего приложение показывает подходящий набор категорий. На главном экране автоматически пересчитываются сумма доходов, сумма расходов и текущий баланс.

### 3. Графики

Кнопка «Графики» открывает окно аналитики с двумя горизонтальными диаграммами: расходы и доходы по категориям. Если операций выбранного типа нет, выводится надпись «Нет данных».

### 4. Синхронизация с Firebase

1. Приложение получает операции из Firebase Realtime Database.
2. Локальные и облачные записи объединяются по идентификатору.
3. При конфликте выбирается запись с более поздним `updated_at`.
4. Итоговый набор сохраняется локально и отправляется обратно в Firebase.

Адрес базы и токен читаются из `.env`, поэтому конфигурация облака не записывается в исходный код.

## Запуск в PyCharm

1. Откройте в PyCharm папку `kivy-expense-tracker`.
2. Выберите Python 3.11 или 3.12 и создайте виртуальное окружение `.venv`.
3. В терминале PyCharm выполните:

```bash
python -m pip install -r requirements.txt
garden install matplotlib
```

4. Запустите файл `main.py` кнопкой Run.

## Настройка Firebase

Создайте файл `.env` в корне проекта и укажите URL Firebase Realtime Database:

```dotenv
FIREBASE_DATABASE_URL=https://example-default-rtdb.firebaseio.com
FIREBASE_AUTH_TOKEN=
```

Токен нужен только при закрытых правилах базы. Файл `.env` не должен публиковаться в GitHub.

## Тестирование

```bash
python -m unittest discover -s tests -v
```

Проверяются сохранение операций, расчёт баланса, группировка по категориям, проверка входных данных, удаление, обработка повреждённого файла, объединение локальных и облачных записей и разрешение конфликтов.

В проекте реализовано 15 автоматических тестов. Все тесты завершаются успешно.

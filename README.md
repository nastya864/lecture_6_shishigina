# Business Expense Tracker

Практическое задание к лекции № 6 «Мобильное приложение» по дисциплине «Проектирование и разработка бизнес-ориентированного программного обеспечения».

Проект расширяет показанный в лекции трекер расходов: добавляет учёт доходов, расчёт баланса, графики и синхронизацию с облачной базой Firebase.

## Задание

1. Добавить графики с использованием Kivy Garden и Matplotlib.
2. Реализовать синхронизацию с облаком через Firebase REST API.
3. Добавить категории доходов и расчёт баланса.

## Соответствие требованиям

| № | Требование | Реализация | Результат |
|---:|---|---|---|
| 1 | Графики | `build_summary_figure()` в `expense_tracker/charts.py` | Графики расходов и доходов по категориям |
| 2 | Синхронизация с облаком | `FirebaseClient` в `expense_tracker/cloud.py` | Загрузка и отправка операций через REST API |
| 3 | Категории доходов | `INCOME_CATEGORIES` в `expense_tracker/models.py` | Зарплата, подработка, продажи, инвестиции, подарки и прочее |
| 4 | Баланс | `total_income`, `total_expense`, `balance` | Баланс рассчитывается как доходы минус расходы |

## Этапы выполнения

### 1. Модель данных

Для каждой операции сохраняются тип, категория, описание, сумма и дата. Данные хранятся локально в формате JSON.

### 2. Доходы, расходы и баланс

Пользователь выбирает тип операции и категорию. На главном экране автоматически рассчитываются общая сумма доходов, расходов и текущий баланс.

### 3. Графики

Кнопка «Графики» открывает две диаграммы: расходы и доходы по категориям. Если операций нет, выводится надпись «Нет данных».

### 4. Синхронизация с Firebase

1. Приложение получает операции из Firebase Realtime Database.
2. Локальные и облачные записи объединяются.
3. Обновлённые данные сохраняются локально.
4. Итоговый набор операций отправляется обратно в Firebase.
